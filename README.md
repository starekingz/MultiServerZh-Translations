# MultiServerZh Translations

MultiServerZh 的 Minecraft 伺服器英語 → 繁體中文詞庫。涵蓋系統聊天、NPC 對話、物品與介面說明，以及計分板、浮空文字等顯示內容。

**本倉庫維護翻譯資料；使用詞庫仍需安裝 MultiServerZh 客戶端模組。** 不需要在伺服器安裝插件。以下操作以 **MultiServerZh 0.5.35** 為準。

## 使用者：安裝與更新

### 支援的伺服器

| 伺服器 | 已標記的連線位址 | 翻譯包 |
| --- | --- | --- |
| OPLegends | `play.oplegends.com` | [oplegends](packs/oplegends.servers.json) |
| PikaNetwork | `mcslr.pika.host` | [pikanetwork](packs/pikanetwork.servers.json) |

模組依**實際輸入的連線位址**尋找翻譯包，顯示名稱取自遠端標記。修改多人伺服器清單中的名稱不影響辨識；其他別名需另行加入標記，不會透過 DNS 或相似網域推測。

### 第一次使用

1. 準備 Minecraft Java **1.21.11**、Fabric Loader **0.19.2 以上**、Fabric API，以及 **Java 21 以上**。
2. 將相容的 MultiServerZh 模組 JAR 放入該遊戲實例的 `mods` 資料夾；更新時替換舊版 JAR。
3. 啟動遊戲並連線到上表的伺服器。
4. 在聊天欄執行：

   ```text
   /mszh import
   ```

5. 等待匯入成功訊息。按 **F9** 可調整翻譯與顯示設定。

`/mszh import` 會自動尋找目前伺服器的翻譯包。舊指令 `/mszh import oplegends` 保留為相同匯入流程的相容入口；不會繞過目前伺服器的位址檢查。

### 詞庫如何更新？

進服時，模組可讀取 GitHub 詞庫並檢查差異；**只有點擊更新提示或手動執行匯入指令，才會套用遠端詞庫**。可在 F9 關閉進服更新檢查。

- 每服的本地詞庫依連線位址隔離，不會沿用上一個伺服器的專屬翻譯。
- 本地沒有詞庫、遠端有對應包時，會提示更新；兩邊都沒有時，會提醒沒有可用翻譯包。
- 已下載的詞庫可離線使用；檢查或下載失敗時仍可使用既有本地資料。
- 匯入會先驗證分類檔並保留備份；本地人工修改會保留，遠端已刪除且本地未修改的舊條目會清理。
- **只有詞庫變更通常不需更換模組。** 若更新涉及匹配、來源分類或顯示修正，則需更新模組。
- 0.5.35 起，僅有分類歸屬變動也會觸發更新提示。

本地設定與資料位於該實例的 `config/multiserverzh/`。用 `/mszh status` 查看目前伺服器與詞庫路徑。

## 使用者：設定與問題排查

### 常用操作

| 操作 | 功能 |
| --- | --- |
| **F9** 或 `/mszh config` | 開啟設定介面 |
| **F8** | 在物品提示框顯示時擷取物品原文、顯示文字與格式資料 |
| 聊天文字上按右鍵 | 依設定執行翻譯檢查、完整訊息擷取，或不處理 |
| `/mszh import` | 手動下載並匯入目前伺服器詞庫 |
| `/mszh reload` | 重新載入本地設定與詞庫 |
| `/mszh toggle` | 開關翻譯 |
| `/mszh status` | 查看目前伺服器、詞庫與引擎狀態 |
| `/mszh test <英文>` | 測試聊天來源的翻譯匹配 |
| `/mszh items panel` | 物品使用獨立翻譯面板 |
| `/mszh items replace` | 物品提示框原地取代 |
| `/mszh scoreboard on`、`off` | 開關計分板翻譯；計分板僅原地取代 |
| `/mszh missing` | 查看未翻譯紀錄數與蒐集狀態 |
| `/mszh missing on`、`off` | 開關未翻譯原文蒐集 |
| `/mszh missing export` | 匯出未翻譯原文與來源明細 |
| `/mszh missing clear` | 清除本服未翻譯紀錄 |
| `/mszh export state` | 匯出目前浮空文字的原文、格式與翻譯狀態 |
| `/mszh online off` | 停用機器翻譯與機翻快取回退 |
| `/mszh cache clear` | 清除本服機翻快取，保留人工詞庫 |

設定預設使用物品翻譯面板、蒐集缺詞，並關閉玩家聊天翻譯與機器翻譯。機器翻譯是選用功能；啟用前需自行準備相容翻譯服務，單純使用本倉庫詞庫不需要啟用。

### 有詞庫，為什麼畫面仍是英文？

按以下順序檢查：

1. 用 `/mszh status` 確認目前連線位址、伺服器與詞庫是否正確。
2. 執行 `/mszh import` 更新；F9 確認該顯示位置的翻譯已啟用。
3. 確認模組版本。0.5.35 修正標題、副標題與快捷列物品名稱查詢錯誤分類的問題。
4. 查看來源分類：**聊天匹配成功，不代表同一文本在物品或浮空文字中也有翻譯。**
5. 擷取完整原文，檢查數值、狀態、換行、格式碼或特殊字型是否不同。

普通漸層文字不因顏色多就一律排除；混淆文字、特定動畫字型及設定中的排除文本可能保留原文。進度條圖形與動態數值應保留，未命中的部分不保證能自動翻譯。

聊天與物品支援既有規則的逐行回退，但不代表任何新句子都能部分命中。`/mszh test` 只測聊天路徑，回報物品或浮空文字問題時請一併提供實際來源。

### 如何回報缺詞或顯示錯誤？

- **缺少翻譯：**執行 `/mszh missing export`，提供原文與配對的 `.sources.json` 來源明細。
- **物品格式錯誤：**用 F8 擷取，附上預期效果與畫面。
- **聊天點擊／格式錯誤：**在 F9 將右鍵功能切為完整擷取，再擷取該訊息。
- **浮空文字錯誤：**執行 `/mszh export state`，提供對應的原文、含格式文字與顯示結果。

請附模組版本、連線位址、文字來源及重現方式。回報前移除不相關的玩家聊天、私訊與個人資料。缺詞紀錄是整理素材，並非可以原封不動發布的翻譯包。

## 開發者：詞庫結構與來源分類

### 檔案結構

```text
packs/
  index.json
  <pack>.servers.json
  <pack>.chat.zh-TW.json
  <pack>.items.zh-TW.json
  <pack>.other.zh-TW.json
  <pack>.zh-TW.json
```

- `index.json`：可發現的翻譯包識別字。
- `<pack>.servers.json`：適用連線位址與顯示名稱。
- 三份分類檔：目前模組的主要下載來源。
- `<pack>.zh-TW.json`：三份分類的去重合併檔，供相容用途；修改分類後須同步產生。

預設匯入流程固定使用同一 Git commit 的索引、伺服器標記及分類檔，避免一次匯入混用不同版本。

### 依模組來源分類，不依句子外觀猜測

| 原文來源 `source_types` | 遠端分類 | 內容 |
| --- | --- | --- |
| `chat` | `chat` | 系統聊天、公告、NPC 對話 |
| `item` | `items` | 物品名稱、Lore、介面物品、快捷列物品名稱 |
| `hologram` | `other` | 浮空文字 |
| `scoreboard` | `other` | 計分板 |
| `actionbar` | `other` | Action Bar |
| `bossbar` | `other` | Boss Bar |
| `title` | `other` | 標題與副標題 |

0.5.35 由模組的 `TextSource` 統一來源紀錄、查詢與未翻譯判定。`manual` 與 `unknown` 的相容路徑使用聊天分類；整理這類紀錄時，仍應先確認實際顯示位置。

**已分類條目不會任意跨分類回退。** 同一文本若同時出現在物品與浮空文字，應在 `items` 和 `other` 都保留相同譯文。不同分類中，同一原文的譯文必須一致；衝突會使匯入被拒絕。未分類的本地舊資料保留相容處理，不應拿來取代遠端分類。

### 詞庫規模

截至 **2026-11-11**；條數包含完整文本與可重用的單行規則，不等同獨立介面數。

| 翻譯包 | 聊天 | 物品 | 其他 | 去重總數 |
| --- | ---: | ---: | ---: | ---: |
| OPLegends | [1,046](packs/oplegends.chat.zh-TW.json) | [2,100](packs/oplegends.items.zh-TW.json) | [305](packs/oplegends.other.zh-TW.json) | [3,421](packs/oplegends.zh-TW.json) |
| PikaNetwork | [96](packs/pikanetwork.chat.zh-TW.json) | [448](packs/pikanetwork.items.zh-TW.json) | [93](packs/pikanetwork.other.zh-TW.json) | [637](packs/pikanetwork.zh-TW.json) |

跨分類可重複收錄同一原文，因此各欄加總可能大於去重總數。

## 開發者：撰寫與提交翻譯

### JSON 與佔位符

鍵是匹配用原文，值是繁體中文譯文；換行使用 JSON 的 `\n`。發布詞庫不可使用空字串作為譯文。

```json
{
  "You have {0} keys.": "你擁有 {0} 把鑰匙。",
  "Seller: {0:player}": "賣家：{0}",
  "Level: {0:number} / {1:number}": "等級：{0} / {1}"
}
```

- 來源與譯文的**佔位符編號集合必須相同**，可在譯文調整順序。
- 同一編號重複出現，代表必須匹配同一個值；目前等級與上限可能不同時，請用不同編號。
- 型別只宣告在來源鍵，譯文仍使用 `{0}` 等不帶型別的形式。
- 支援 `text`、`number`、`integer`、`player`、`state`。未指定型別的 `{0}` 為不跨換行的文字。
- `player` 限 Minecraft 玩家名稱字元及長度，不能用來匹配任意暱稱或幫派名。
- `state` 僅匹配引擎列舉的狀態，例如 `ON`、`OFF`、`LOCKED`、`MAX`；不同狀態需要不同中文時應分開寫。
- 來源是固定文字與佔位符模板，**不是任意正規表示式**。

### 翻譯原則

1. 沿用同服既有附魔、貨幣、寵物與功能名稱；數字、單位、網址、指令與作答答案須保持語意正確。
2. 保留必要空行、欄位順序、進度條圖形與格式資訊；格式問題需用完整 Component／含格式擷取資料確認。
3. 優先為數字、玩家名稱或狀態變動建立有明確固定文字的規則；避免只含佔位符與標點的廣泛規則。
4. 逐行規則必須能獨立表達原意。對齊來源與譯文後再拆行；同一行有不同語意或譯法時，不應自動合併。
5. 玩家自由發言、私訊、動畫逐字顯示的中間片段、機翻快取及 missing 原始匯出檔，不直接納入發布詞庫。帶玩家名稱的系統公告則依完整句型整理。
6. 有意保留的動畫標題或特殊格式文字，應保留原文／使用排除設定；不要藉由猜測字元位置修改格式。

### 建議貢獻流程

1. 從遊戲匯出原文與來源，去重並排除不應翻譯的內容。
2. 比對現有詞庫：先區分缺詞、分類遺漏與格式／匹配問題。
3. 修改對應分類檔；多來源文本在各適用分類保留一致譯文。
4. 同步產生去重合併檔，確認沒有重複 JSON 鍵、空譯文、佔位符遺漏或跨分類衝突。
5. 驗證原始範例，以及不同數值／狀態的範例。若涉及模組修改，另測來源路徑、missing 判定與實際遊戲顯示。
6. 提交 Pull Request，說明伺服器、來源分類、變更範圍與驗證結果；附必要的重現樣本。

不要為了消除 missing 而新增過度寬鬆的規則。字串匹配成功也不等於顏色、粗體、換行與點擊事件已通過遊戲實測。

## 開發者：新增伺服器

1. 選擇唯一的小寫識別字，例如 `example`，加入 [packs/index.json](packs/index.json) 的 `packs` 陣列。
2. 新增 `packs/example.servers.json`：

   ```json
   {
     "schema_version": 1,
     "server_name": "Example Server",
     "server_ips": ["play.example.com"]
   }
   ```

3. 新增 `example.chat.zh-TW.json`、`example.items.zh-TW.json`、`example.other.zh-TW.json`，填入各來源的有效譯文，並產生 `example.zh-TW.json`。
4. 確認每個標記位址只對應一個翻譯包；重複標記會被拒絕。
5. 以實際連線位址測試發現、匯入、顯示名稱與換服隔離。

位址比對會忽略大小寫、結尾的點與預設連接埠 `25565`；非預設連接埠需明確標記。其他網域別名也需逐一列出。

自訂單檔 URL 使用同目錄的位址標記，例如 `custom.json` 對應 `custom.servers.json`；此為未分類單檔相容流程，不等同索引中的三分類翻譯包。
